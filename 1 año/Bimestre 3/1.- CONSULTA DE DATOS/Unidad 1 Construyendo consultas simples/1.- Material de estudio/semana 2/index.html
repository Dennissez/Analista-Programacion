Módulo 1: Requisito Previo obligatorio

¿Qué es una Transacción y el comando COMMIT?

🔄 Concepto de Transacción

En bases de datos, las operaciones de modificación (DML) no alteran el disco de manera definitiva inmediatamente.

Una Transacción es un conjunto de instrucciones DML que se ejecutan como una sola unidad de trabajo en la memoria temporal del servidor.

Principio: Si algo falla durante la transacción, se puede deshacer todo para no dejar la base de datos corrupta o a medias.
✅ Confirmación con COMMIT

La semana 2 enfatiza que tus cambios de escritura no son permanentes hasta ejecutar un COMMIT.

  • Estado Pendiente: Solo tú ves los cambios en tu sesión actual. Si la conexión cae, se pierden.
  • COMMIT: Guarda de forma definitiva y física en la base de datos todos los cambios pendientes.
  • ROLLBACK: Cancela y deshace todas las modificaciones no guardadas.

Claves y Tipos de Datos al Insertar/Modificar

🔑 Reglas de Integridad

Antes de modificar o insertar filas, debes recordar estas restricciones básicas:

  • Primary Key (PK): No permite valores duplicados ni nulos. Si intentas insertar un ID repetido, la BD arrojará error.
  • Foreign Key (FK): No puedes insertar un valor que no exista previamente en la tabla de origen (ej: asignar un departamento 999 si no existe en la tabla de departamentos).
  • NOT NULL: Si una columna exige dato obligatorio, no puedes omitirla ni asignarle NULL.
📝 Formato de Datos

Recuerda la sintaxis correcta según el tipo de dato:

Tipo de Dato Regla en SQL Ejemplo
Números Sin comillas 15000, 10.5
Textos Comillas simples obligatorio 'Finance', 'SA_REP'
Fechas Comillas simples / Funciones '01/01/2026', SYSDATE

Módulo 2: Semana 2 — Filtrado Avanzado

Operadores Lógicos: AND, OR y NOT

AND (Y lógico)

Exige que TODAS las condiciones sean verdaderas para incluir la fila en el resultado.

SELECT * FROM employees
WHERE salary >= 10000
  AND job_id LIKE '%MAN%';

Muestra solo empleados que ganen >= 10000 Y ADEMÁS su cargo contenga 'MAN'.

OR (O lógico)

Basta con que AL MENOS UNA de las condiciones sea verdadera.

SELECT * FROM employees
WHERE salary >= 17000
   OR hire_date > '01/01/2008';

Muestra si ganan >= 17000 O BIEN si ingresaron después de 2008.

NOT (Negación)

Invierte el resultado lógico de la condición que le sigue.

SELECT * FROM employees
WHERE job_id NOT IN 
 ('IT_PROG', 'SA_REP');

Muestra todos los empleados cuyo cargo NO SEA IT_PROG ni SA_REP.

Reglas de Precedencia y Uso de Paréntesis

⚖️ Orden de Evaluación por Defecto

Cuando mezclas varios operadores en un WHERE, SQL los evalúa en este estricto orden de prioridad:

  1. Operadores Aritméticos (*, /, +, -)
  2. Operador de Concatenación (||)
  3. Comparaciones (=, >, <, >=, <=)
  4. IS NULL, LIKE, IN
  5. BETWEEN
  6. Condición Lógica NOT
  7. Condición Lógica AND (Se evalúa ANTES que el OR)
  8. Condición Lógica OR
⚠️ ¡Cuidado con la trampa de AND y OR!

Dado que AND se ejecuta antes que OR, el resultado puede cambiar radicalmente si no usas paréntesis:

-- Muestra SA_REP de cualquier sueldo, O AD_PRES con sueldo > 15000
WHERE job_id = 'SA_REP' OR job_id = 'AD_PRES' AND salary > 15000;

-- Usando paréntesis: Muestra SA_REP o AD_PRES, PERO AMBOS obligatoriamente > 15000
WHERE (job_id = 'SA_REP' OR job_id = 'AD_PRES') AND salary > 15000;

Módulo 2: Semana 2 — Escritura de Datos (DML)

Sentencia INSERT: Agregar Filas Nuevas

➕ Formas de Insertar

1. Declarando Columnas (Recomendado): Es más seguro porque no depende del orden estricto de la tabla.

INSERT INTO departments (department_id, department_name, manager_id, location_id)
VALUES (70, 'Public Relations', 100, 1700);

2. Sintaxis Abreviada: Omites las columnas, pero debes pasar los valores en el orden exacto de la tabla.

INSERT INTO departments
VALUES (70, 'Public Relations', 100, 1700);
🔮 Inserción de Valores Nulos y Especiales

Campos Nulos:

  • Explícita: Escribes la palabra NULL en VALUES.
  • Implícita: Omites la columna en la lista de campos.

Valores Especiales (Ej: Fecha actual del sistema):

INSERT INTO employees (employee_id, last_name, hire_date, ...)
VALUES (113, 'Popp', SYSDATE, ...);

Objeto Secuencia (SEQUENCE)

🔢 ¿Qué es una Secuencia?

Un objeto independiente de la base de datos que genera números correlativos automáticos (ideal para autoincrementar la Clave Primaria).

CREATE SEQUENCE dept_deptid_seq
  START WITH 120
  INCREMENT BY 10
  MAXVALUE 9999
  NOCYCLE;
⚙️ Uso con Pseudocolumnas
  • NEXTVAL: Incrementa y devuelve el **siguiente** valor disponible.
  • CURRVAL: Muestra el valor **actual** generado en la sesión.

Ejemplo de uso al insertar:

INSERT INTO departments (department_id, department_name, location_id)
VALUES (dept_deptid_seq.NEXTVAL, 'Support', 2500);

Módulo 2: Semana 2 — Modificación de Datos (DML)

Sentencia UPDATE: Modificar Registros

✏️ Sintaxis y Modificación Filtrada

Permite cambiar valores en una o más columnas de registros existentes.

UPDATE employees
SET salary = salary * 1.25
WHERE salary < 5000;

Aumenta un 25% el sueldo, pero ÚNICAMENTE a los empleados que ganan menos de 5000.

🚨 ¡Peligro! Omitir la cláusula WHERE

Si ejecutas un UPDATE sin incluir la cláusula WHERE, se modificará TODA LA TABLA sin excepción.

-- ¡CUIDADO! Esto cambia el sueldo a TODOS los empleados de la BD
UPDATE employees
SET salary = 10000;
Regla de oro: Revisa siempre dos veces la cláusula WHERE antes de ejecutar un UPDATE.

Módulo 2: Semana 2 — Eliminación de Datos

DELETE vs TRUNCATE: Limpieza de Registros

🗑️ Sentencia DELETE (DML)

Elimina filas específicas mediante una condición. Se puede deshacer con ROLLBACK si no has hecho commit.

-- Elimina registros específicos
DELETE FROM departments
WHERE department_name = 'Finance';

-- Si omites WHERE, borra todas las filas pero mantiene el espacio
DELETE FROM employees;
⚡ Sentencia TRUNCATE (DDL)

Elimina TODAS las filas de una tabla de forma ultra rápida.

TRUNCATE TABLE employees;
  • Diferencia clave: Es una instrucción DDL (no DML).
  • COMMIT implícito: No se puede deshacer con ROLLBACK. Los datos se pierden de inmediato.
  • Liberación de espacio en memoria instantánea.

Módulo 2: Conclusión

Resumen de Comandos DML y Siguientes Pasos

Comando Acción Requiere WHERE Reversible antes de COMMIT
INSERT Añade filas nuevas No Sí (con ROLLBACK)
UPDATE Modifica campos existentes Sí (salvo cambio masivo) Sí (con ROLLBACK)
DELETE Elimina filas Sí (salvo vaciado total) Sí (con ROLLBACK)
TRUNCATE Vacía la tabla completa No (siempre borra todo) NO (COMMIT automático)
